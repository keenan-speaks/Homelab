# Contributing

Thank you for your interest!

## Project Goals

The primary goals of this project are:

* Documentation
* Reproducibility
* Maintainability
* Continuous learning

## Documentation Standards

New documentation should:

* Use clear Markdown formatting.
* Explain the purpose of each component.
* Describe architectural decisions (where appropriate).
* ***Avoid publishing sensitive information.***

## Commit Messages

Commits should describe a single change.

Examples:

* Add Jellyfin documentation
* Document backup strategy
* Update architecture diagrams

Please avoid generic commit messages such as:

* Updates
* Fixes
* Misc changes

## Security

Never commit:

* Secrets
* Passwords
* API keys
* Private certificates
* Production configuration files
